# 20 real-app acceptance scenarios

Release checklist for Vortex 2.0.0-beta.1. Items are intentionally unchecked: inclusion in this document does not mean the real-app scenario passed. Record device/Android/app versions, script variant, expected result, elapsed action/capture time and evidence for each execution.

Use Settings, Chrome, Photos, StockPilot and IndiaMART where installed. Prepare test accounts, a sample photo and uniquely named products. Use the selected device in the ADB panel; commands below exclude `adb -s SERIAL`. For recorded business flows, verify both Plain and POM and ensure Both exposes one default discoverable variant.

1. [ ] **Native inspection and copying — Settings.** Inspect Search without activating it. Copy locator, ID, text, class, bounds, pixels, percentages, ADB tap and MobileWright tap. Turn copy-on-selection on and off. Pass when the selected control matches every copy/highlight and inspection sends no device action.
2. [ ] **Repeated controls — StockPilot products.** Inspect multiple cards with the same labels. Record a product-specific scoped locator, change list position, and replay. Exercise count assertions and positional warnings. Pass when the intended product is selected or ambiguity fails clearly.
3. [ ] **Native navigation — IndiaMART.** Open Seller Tools, the footer Add Products control and My Products. Add preconditions and destination checks. Pass when every transition reaches its asserted screen and a failed tap cannot reuse the preceding state as success.
4. [ ] **States and waits — Settings/app form.** Toggle a switch, select a radio option and open/dismiss a dialog. Cover visible/hidden, enabled/disabled, checked/unchecked, selected/unselected, exact/contains text and count when exposed. Exercise waits for visible, hidden and enabled; one deliberately unmet wait must time out.
5. [ ] **Input semantics — StockPilot search.** Replace `rice` with `sugar`, clear, then append with Quick type. Include spaces, quotes and `A B & C`. Pass when replacement, clear and append remain distinct and text cannot turn into an additional shell command. Unsupported input must fail explicitly.
6. [ ] **Whole incorrect OTP — IndiaMART.** Start with empty boxes, focus the first and send `2455` once. Assert `Please enter correct OTP` after the result appears. Compare full capture and screenshot-only feedback. Pass when all digits enter and an early image is not mistaken for proof of failure or success.
7. [ ] **Sensitive input.** Record a password/OTP as sensitive. Inspect drafts, saved recordings and copied Plain/POM output. Replay without its environment variable, then with a test value. Pass when stored steps contain references/placeholders and missing values fail before typing.
8. [ ] **Keyboard/navigation.** In Settings search, test Enter, Delete, Tab, directional keys, Back, Home and Recent Apps. Use `shell input keyevent KEYCODE_DEL`. Test Back hiding the keyboard and preserve command ordering in replay.
9. [ ] **Swipes and scroll-to.** Exercise all four swipe directions on suitable content, including custom coordinate/duration arguments. Record a known scroll target, reset list position and replay. Pass when the destination is reached instead of accepting an arbitrary swipe.
10. [ ] **Long press/double tap — Photos.** Double-tap a sample image to zoom, then long-press its thumbnail to select it. Check locator and coordinate variants. Pass when these are distinct interactions with the correct resulting state.
11. [ ] **Permissions and photo picker.** From an app's Add Photo action, inspect the system picker and permission dialog. Select a sample image, then cancel the draft. Pass when overlay controls work and hidden app controls behind them are not selected accidentally.
12. [ ] **Exposed WebView controls — IndiaMART.** Inspect product text, Edit and a price input. Record exposed text/ID/type locators, including an empty editable field, and assert a draft value without submitting it. Pass when replay targets the field itself instead of a labelled parent.
13. [ ] **Opaque controls/coordinates.** Record keypad or unlabelled WebView actions using explicit coordinates with meaningful before/after checks. Copy coordinates and tap statements. Pass when the chosen point is sent and coordinate dependence is visible in review.
14. [ ] **Lifecycle and URLs — Chrome.** Launch, open `https://example.com`, close and relaunch. Exercise `shell am force-stop com.android.chrome` and the URL preset. Pass when only the selected package is affected and exported lifecycle steps avoid unnecessary duplicate startup/cleanup.
15. [ ] **Screenshots/checkpoints.** Capture a screen and dialog using a checkpoint and `exec-out screencap -p`. Open downloaded output and replay attachments. Pass when PNGs are valid, dimensions match and evidence reflects the intended state. A preview must expose no stale hit targets.
16. [ ] **Diagnostics/capture choices.** Run `shell wm size`, `shell dumpsys activity activities`, `shell dumpsys input_method`, `shell pm list packages` and `shell getprop`. Compare no capture, preview and full capture. Pass when output is readable, no-capture avoids a tree dump and full Refresh restores inspection.
17. [ ] **Custom ADB/copy/execution modes.** Paste a command and a JSON array; try `shell sh -c "echo inspector_ok"`. Push/pull a small disposable file. Check Run only, Add to script, Run & record and copy/paste. Edit recorded arguments and timeout. Pass when adding executes nothing, running only adds nothing, commands execute once, quoting survives and timeout changes reach replay.
18. [ ] **Recovery and device identity.** Use an invalid command, disconnect/reconnect, and test a second device when available. Reject a pasted mismatching `-s` serial. Rotate the emulator before coordinate replay; test Volume and Power/Wake keys. Pass when failures are clear, no other device is chosen silently, changed geometry is rejected and refresh recovers.
19. [ ] **Edits/drafts/conflicts.** Edit five recorded steps; duplicate, reorder, delete and undo. Restore after browser reload and server restart. Exercise conflicting tabs and a hand-edited generated file. Pass when changes persist, stale writes conflict, explicit discard stays discarded and hand edits are preserved for review.
20. [ ] **Business flow/export/report.** Create a uniquely named test product, edit its price, reopen/assert persistence, then delete only that product and assert absence. Copy/export Plain, POM and Both. Deliberately fail a check, cancel a run and inspect reports/checkpoints/benchmarks. Pass when errors identify the step, cancelled runs free the device and copied scripts retain required helpers.

## Expected unsupported behavior

Live CSS/XPath/DOM acquisition, dedicated hide-keyboard export and native activity assertions are not success requirements for this beta. They must be unavailable or report an explicit generation limitation, not silently disappear from an exported test. Raw ADB steps must refuse simulated replay instead of touching hardware.

## Promotion gate

After recording checklist evidence, require ten consecutive unattended Add → Edit → Delete cycles on a real phone with unedited UI-generated scripts and unique test products. Keep failures as evidence; do not mask repeated writes with silent retries. These 20 scenarios cover current action categories and presets, not every possible ADB command or application behavior.
